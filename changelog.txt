=== Unreleased

* Event loop for the router core: one thread owns protocol state, other
  threads use #post and #call (OSPFv2::EventLoop)
* Timer scheduler on a binary heap, with restartable one shot timers and
  drift-free periodic timers with optional jitter (OSPFv2::Scheduler)
* Real and fake clocks. With Clock::Fake, tests run hours of protocol
  time in milliseconds and repeat exactly (OSPFv2::Clock)
* The simulator still uses the thread-per-timer OSPFv2::Timer for now
* Router core (OSPFv2::Core): areas, broadcast and point-to-point
  interfaces, interface state machine and DR/BDR election, neighbor state
  machine with 2-Way and a master/slave DD exchange, per-area and AS-wide
  LSDBs, RFC 2328 section 13 flooding with per-neighbor retransmission
  lists and delayed acks, router-LSA and network-LSA origination with
  MinLSInterval, LSRefreshTime refresh and MaxAge flushing
* Core packet codec keeps received LSAs byte for byte, so they are
  flooded unchanged; cross-checked against the existing packet classes
* Simulator fix: an ack only counts for the instance it names
  (RFC 2328 13.7)
* Packet authentication for the core (OSPFv2::Core::Auth): null, simple
  password, keyed MD5 (RFC 2328 D) and HMAC-SHA-1/256/384/512
  (RFC 5709). Several keys per interface for rollover, one send key,
  mixed algorithms allowed. Replay check on the cryptographic sequence
  number, kept per router id, plus a check that a LAN neighbor's address
  and router id stay paired, so a packet replayed from a spoofed or
  another neighbor's address is dropped. Our sequence number starts from
  the wall clock, survives key changes and stops at 2**32 - 1. Bigger
  digests shrink the room for LSAs so packets still fit the MTU
* Interop tests against FRRouting ospfd in network namespaces, with and
  without authentication (OSPFV2_FRR=1, run as root; a CI job runs them)
