=== Unreleased

* Event loop for the router core: one thread owns protocol state, other
  threads use #post and #call (OSPFv2::EventLoop)
* Timer scheduler on a binary heap, with restartable one shot timers and
  drift-free periodic timers with optional jitter (OSPFv2::Scheduler)
* Real and fake clocks. With Clock::Fake, tests run hours of protocol
  time in milliseconds and repeat exactly (OSPFv2::Clock)
* The simulator still uses the thread-per-timer OSPFv2::Timer for now
* Router core (OSPFv2::Core): areas, broadcast and point-to-point
  interfaces, interface state machine and DR/BDR election, neighbor state
  machine with 2-Way and a master/slave DD exchange, per-area and AS-wide
  LSDBs, RFC 2328 section 13 flooding with per-neighbor retransmission
  lists and delayed acks, router-LSA and network-LSA origination with
  MinLSInterval, LSRefreshTime refresh and MaxAge flushing
* Core packet codec keeps received LSAs byte for byte, so they are
  flooded unchanged; cross-checked against the existing packet classes
* Simulator fix: an ack only counts for the instance it names
  (RFC 2328 13.7)
* Packet authentication for the core (OSPFv2::Core::Auth): null, simple
  password, keyed MD5 (RFC 2328 D) and HMAC-SHA-1/256/384/512
  (RFC 5709). Several keys per interface for rollover, one send key,
  mixed algorithms allowed. Replay check on the cryptographic sequence
  number, kept per router id, plus a check that a LAN neighbor's address
  and router id stay paired, so a packet replayed from a spoofed or
  another neighbor's address is dropped. Our sequence number starts from
  the wall clock, survives key changes and stops at 2**32 - 1. Bigger
  digests shrink the room for LSAs so packets still fit the MTU
* Interop tests against FRRouting ospfd in network namespaces, with and
  without authentication (OSPFV2_FRR=1, run as root; a CI job runs them)
* ospfd: runs the core from a configuration file, answers a JSON
  management API on a Unix socket, reloads on SIGHUP
* Junos-style configuration (OSPFv2::Config): set and delete statements
  with unique-prefix abbreviations, curly and set displays, hidden
  secrets, shared candidate, commit, commit check, compare, rollback 1..9.
  Metric and authentication changes apply without restarting the
  interface; interfaces missing on the host wait until they appear
* ospf-cli: Junos and IOS forms of show ospf neighbor, interface,
  database, overview, log and statistics, clear ospf neighbor, pipes
  (match, except, count, last, display json, display set), ? help and
  Tab completion, one-shot mode with -c
* Routing table calculation (OSPFv2::Core::Spf, RFC 2328 16): intra-area
  Dijkstra with the two-way check, next hops on LANs and point-to-point
  links, equal-cost multipath (16 paths), inter-area routes through ABRs,
  AS external routes type 1 and 2 with forwarding addresses and ASBRs
  found through type 4 summaries. A 1,024-router grid takes about 40 ms
* SPF back-off per RFC 8405 (OSPFv2::Core::SpfScheduler): initial 50 ms,
  short 200 ms, long 5 s, time to learn 500 ms, holddown 10 s (the
  RFC's suggested values). Runs when an
  LSA's contents change, an LSA reaches MaxAge, or an interface or
  adjacency comes or goes
* The router keeps its routing table and tells listeners what changed
  (Instance#routes, #on_route_change); the last 100 SPF runs are kept
* ospf-cli: show ospf route [detail], show ip ospf route, show ip route
  ospf; show ospf log and show ip ospf statistics now show SPF runs;
  protocol events moved to show ospf events, packet counters on IOS to
  show ip ospf traffic
* Routes into the Linux kernel (OSPFv2::Fib): a manager that keeps the
  kernel in line with the routing table, and a pure Ruby rtnetlink
  backend. Routes through a gateway only, ECMP as one multipath route,
  our own protocol id (89) so other routes are never touched, new routes
  never overwrite another route at the same prefix and metric, replace
  before delete, retries for refused routes, a 60 s reconcile that repairs
  drift, withdraw on clean stop, routes kept across a crash until OSPF
  has converged
* routing-options kernel metric, protocol, table and no-install; ids other
  daemons use are refused, and routes left under old settings are swept
* ospf-cli: show route protocol ospf (Junos) and show ip route ospf (IOS)
  show what is in the kernel and flag anything that differs; the
  overview shows the kernel route count
* Interop: on the FRR topology our routes reach the kernel, carry pings
  across it, survive a crash and restart, and leave on a clean stop.
  Netlink tests in a network namespace (run as root)
* Area border router: B bit, type 3 summaries for other areas' routes and
  type 4 summaries for AS boundary routers (RFC 2328 12.4.3), Appendix E
  link state ids, withdrawn when no longer wanted
* AS boundary router: AS-external-LSAs (12.4.4) and the E bit, from a
  Junos-style export policy (policy-options policy-statement with
  protocol direct|static, route-filter exact|orlonger|longer|upto, then
  metric, external type, tag, accept, reject; protocols ospf export)
* Stub and totally stubby areas (area N stub [default-metric M]
  [no-summaries]): no E bit, no AS-external LSAs or type 4 summaries,
  a default summary from the ABR; neighbors that disagree are refused
* NSSA (RFC 3101; area N nssa [default-lsa default-metric M metric-type
  1|2] [no-summaries]): N bit in hellos, type 7 LSAs with the P bit and a
  forwarding address from an NSSA ASBR (P clear from an NSSA ABR, which
  originates the type 5 itself), type 7 routes in SPF with the 2.5
  preference rules, translation into type 5 by the NSSA ABR with the
  highest router id, the optional type 7 default and the no-summaries
  type 3 default
* Interop: stub, totally stubby and NSSA areas behind our ABR, with FRR
  inside; equal-cost failover in the kernel within the dead interval
* Area border routers per RFC 3509: attached to the backbone and another
  area; without a backbone neighbor, every area's summaries count
* NSSA review fixes: border routers ignore each other's type 7 default,
  no type 4 summaries for NSSA ASBRs, the translator must be on the
  backbone, honors the Nt bit and keeps the role 40 s after losing it,
  a type 7 forwarding address must have its longest match in the NSSA
* Equal-cost externals through different forwarding addresses keep both
  paths; one area per intra-area route
* Summaries and externals are recomputed only when routes or area state
  change, our own summaries and externals no longer trigger SPF, and LSA
  refreshes are jittered
* Export policy route filters match as on Junos (longest filter prefix
  decides); a kernel read error keeps the static routes advertised
* Changing an area's default metric, no-summaries or default-lsa no longer
  restarts its interfaces; only a change of area type does
* Configuration: a leaf or flag may be followed by its siblings on one
  line, as on Junos (set ... stub default-metric 10 no-summaries)
* Fix: a router in two areas tracked its own LSAs by LSA key alone, so
  its router-LSA in the second area could stay stale
* Interop: our router as ABR and ASBR between two FRR routers; FRR's
  tables match our SPF from their seats and traffic crosses our router
* Interop test: on a four-router FRR topology (ECMP, an ABR, type 1 and
  type 2 externals), SPF over our database gives FRR's own table
  exactly, before and after a metric change and a withdrawn external
